An end-to-end blueprint for moving a returned smart meter from sourcing and store receipt through evidence-controlled analysis, RCA, CAPA, back-tracing and closure.

How to read this page

Start with the source-system matrix. Then follow the numbered process. The module section shows ownership; the case section shows branches and exceptions.

System in one line

Six connected movements

The physical meter and its digital evidence move together. Each handoff updates the same case record.

01Source returnComplaint, return authorization and dispatch context.
02Receive in storeGRN, custody, location, photographs and identity.
03Prepare evidenceGenealogy, optical extraction and readiness gates.
04Analyse failureSafe tests, observations, hypotheses and teardown.

06Back-trace & learnBatch exposure, supplier/process link and recurrence.

4 · Case paths

Not every return follows the same branch

All cases share intake, identity and evidence control. The analysis branch changes according to the reproduced symptom and available evidence.

Confirmed hardware failure

Symptom reproduced; electrical/component evidence supports a cause.

Path: core test → targeted test → teardown → RCA → CAPA

Communication failure

Local meter functions pass; optical/RF/network evidence becomes the diagnostic branch.

Path: core test → comms test → firmware/configuration evidence

Relay / switching failure

Safety and controlled-load tests examine command, drive path, contacts and mechanism.

Path: safe screen → relay recipe → targeted teardown

RTC / battery drift

Battery domain, RTC accuracy, event chronology and storage conditions are compared.

Path: battery test → RTC observation → component/environment branch

Terminal heating

Highest-risk branch; external evidence is preserved before any energization or opening.

Path: safety block → thermal/terminal inspection → controlled specialist route

No fault reproduced

Core and complaint-specific tests pass; system records coverage and missing field conditions.

Outcome: NFR with tested conditions, not an invented cause

Inconclusive

Evidence is contradictory or insufficient after approved tests.

Outcome: explicit unknowns, confidence and escalation / retention plan

Blocked exception

Identity mismatch, missing evidence, unsafe condition, expired calibration or unauthorized action.

Outcome: stop workflow until resolved or formally waived

HES is intentionally not part of this initial trace. It will be integrated later to add field communication and event chronology after the core sourcing, store, laboratory, RCA, CAPA and back-tracing flow is stable.
6 · Closure logic

One case, three independent endings

The case is visible as one record, but closure is not collapsed into one status.

Technical closure

Required evidence complete, diagnosis classified, structured RCA approved and report state recorded.

Commercial closure

Repair order, replacement dispatch, customer receipt and liability decision completed through authorized processes.

CAPA closure

Actions implemented and effectiveness rule passed across the defined population and observation window.
