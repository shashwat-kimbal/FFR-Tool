RCA intelligence core

Three AI analyses feed one diagnostic reasoning loop

RCA is not generated directly from a complaint. It is synthesized only after independent image, digital-data and instrument analyses have produced evidence that can be compared, contradicted and tested.

Independent evidence analysis

Vision-based AI analysis

Compares external and internal images with the correct model, PCB, BOM and configuration baseline.

  • Burn, corrosion, moisture, terminal heating and impact
  • Missing/wrong/displaced components and connector issues
  • Solder, contamination, carbon tracking and PCB damage
  • Outputs observations and regions—not causal claims
BCS/DLMS data-based AI analysis

Interprets the preserved digital package while retaining raw trace and object-map provenance.

  • Reset/event/tamper chronology and RTC drift
  • Firmware/configuration mismatch and status-register patterns
  • Load survey, instantaneous, power-quality and data-gap signatures
  • Relay/communication/battery history and access failures
Equipment-reading AI analysis

Interprets calibrated measurements against variant-specific limits, golden units and expected waveforms.

  • Power path, PSU rails, battery, MCU reset/clock and relay
  • Metrology, communication and complaint-specific function
  • Raw value → normalized finding → hypothesis impact
  • Automatic safety stop and invalid-test detection

Diagnostic reasoning agent

  1. Creates multiple plausible hypotheses
  2. Links supporting, contradictory and missing evidence
  3. Scores confidence without hiding uncertainty
  4. Chooses the approved test with highest information gain
  5. Sends the test to the laboratory workflow
  6. Updates every hypothesis from the new result
  7. Stops at confirmed, probable, NFR or inconclusive
  8. Passes the resolved evidence graph to RCA synthesis
Reported observation→Reproduced symptom→Failed function→Subsystem→Component / node→Physical mechanism→Initiating cause→Contributors→Origin→Escape point→Confidence + evidence

Structured RCA record

Searchable fields, evidence links, confidence, contradictions, missing evidence and approval history.

Internal RCA report

Full technical detail, hypothesis history, raw/derived results, liability recommendation and CAPA.

Customer-safe report

Generated from the approved record without internal scores, unsupported blame or billing conclusions.

RCA feedback

Confirmed signature flows to CAPA, MES back-tracing, test-rule improvement and population learning.

After RCA

CAPA and back-tracing close the learning loop

The approved RCA becomes the input; the system does not ask users to recreate the cause in another document.

CAPA module

  • Contain potentially affected meters
  • Correct the returned case
  • Remove the confirmed root cause
  • Prevent recurrence in related product/process
  • Define owner, due date, metric, target and pass rule
→

Back-tracing module

  • Query MES by PCB/batch/firmware/line/supplier/process
  • Link similar RCA signatures and visual/DLMS/test patterns
  • Estimate affected population
  • Select representative samples and identify outliers
  • Create systemic alert or shared RCA/CAPA candidate
→

Effectiveness & closure

  • Monitor recurrence against baseline and target
  • Verify action evidence and observation window
  • Reopen failed CAPA automatically
  • Send validated feedback to MES/test knowledge
  • Track SAP RO/return and scrap status separately
HES is a later-phase addition. Once the core intake, Store, MES, BCS/DLMS, laboratory, RCA, CAPA and back-tracing modules are stable, HES will add field communication and event chronology as another evidence input to the same diagnostic reasoning loop.
